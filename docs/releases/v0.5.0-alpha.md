# OpsCustodian v0.5.0-alpha

OpsCustodian is an evidence-based control plane for agentic DevOps. This first
public alpha focuses on a useful offline workflow: discover agentic automation,
build a vendor-neutral Agent Bill of Materials, explain effective access, and
detect dangerous permission drift before it reaches production.

## Try it in five minutes

No AI model, database, cluster, cloud account, or token is required.

```bash
opscustodian scan --output agentbom.demo.json ./examples/scan-input
opscustodian report --bom agentbom.demo.json --output opscustodian-demo.html
opscustodian diff \
  ./examples/scope-expansion/agentbom.before.json \
  ./examples/scope-expansion/agentbom.after.json
```

The final command identifies a critical change from write access to one
production workload to admin access across all production workloads. Read the
[Quick Start](https://github.com/OpsNeuron/OpsCustodian/blob/v0.5.0-alpha/docs/QUICKSTART.md)
for source-build and Windows commands.

## What is included

- Offline discovery for GitHub Actions, GitHub Agentic Workflows, agent and
  instruction Markdown, MCP configuration, and Kubernetes declarations.
- A versioned, evidence-backed Agent BOM with typed assets, capabilities,
  credentials, ownership, relationships, diagnostics, and access paths.
- Semantic drift detection with stable finding identities, calibrated severity,
  source evidence, explanations, and remediation identifiers.
- GitHub Actions permission, trigger, runner, dependency, reusable-workflow,
  secret propagation, and untrusted-data-flow analysis.
- Kubernetes workload, ServiceAccount, RBAC, token projection, aggregation,
  privilege-escalation, and declared-versus-effective access analysis.
- MCP provenance, pinning, transport, import, network, permission, and
  configuration-precedence analysis.
- Terminal, JSON, YAML, SARIF, self-contained HTML, audit JSONL, OPA policy, and
  GitHub Action integration contracts.
- An experimental authenticated organization control-plane foundation with
  PostgreSQL persistence, repository ingestion, lifecycle queries, audit events,
  readiness, and secret-safe configuration.

## Security properties

- Repository scanning is offline and read-only by default.
- Evidence is retained for inferred capabilities and effective-access paths.
- Credential references are recorded; secret values must never enter the BOM.
- Malformed supported artifacts produce diagnostics instead of hiding results
  from the remainder of the repository.
- Generated HTML is self-contained, escapes repository values, and contains no
  external scripts or network resources.

## Alpha limitations

This release is for evaluation and feedback. Agent BOM and server contracts may
change before v1.0.

- The organization server remains experimental. PostgreSQL, OPA, OTLP,
  Kubernetes deployment boundaries, and GitHub provider paths have been
  exercised in disposable environments; this evidence is not a production
  support or availability claim.
- The default deployment is single-replica. The two-replica overlay is
  experimental and is not an HA support claim.
- Offline effective-access analysis is evidence from configuration, not a live
  authorization decision from a provider API.
- Parser coverage is intentionally conservative. Review diagnostics before
  interpreting absence of an asset or capability.
- The GitHub Action has produced a real SARIF code-scanning alert in a
  disposable public repository. Release artifacts and provenance still require
  verification from the published prerelease before any production
  recommendation.

## Installation and verification

Download the archive matching your operating system together with
`SHA256SUMS`. Verify the complete SHA-256 hash before extraction, then run:

```bash
opscustodian version
```

Release assets include Linux amd64/arm64, macOS amd64/arm64, Windows amd64,
SHA-256 checksums, a CycloneDX SBOM, and GitHub build provenance. See the
[installation guide](https://github.com/OpsNeuron/OpsCustodian/blob/v0.5.0-alpha/docs/INSTALLATION.md)
and [release checklist](https://github.com/OpsNeuron/OpsCustodian/blob/v0.5.0-alpha/docs/ALPHA_RELEASE_CHECKLIST.md).

## Feedback wanted

The most useful early feedback is a sanitized repository fixture or diagnostic
showing:

- an agentic asset OpsCustodian did not discover;
- a permission path it inferred incorrectly;
- a dangerous change that should have produced a stronger finding;
- an output or explanation that a platform team could not act on.

Do not attach secret values, private keys, tokens, signed URLs, or proprietary
repository contents to public issues.
