# Support

OpsCustodian is pre-v1 open-source software maintained on a best-effort basis.
No response-time, availability, or production-support SLA is provided.

## Start here

1. Follow the [Quick Start](docs/QUICKSTART.md).
2. Check the [beta support matrix](docs/BETA_SUPPORT_MATRIX.md) and
   [current limitations](docs/LIMITATIONS.md).
3. Search existing issues before opening a new report.

## Public support requests

Use the repository issue forms for reproducible bugs, sanitized parser
compatibility fixtures, and first-user feedback. Include the OpsCustodian
version, platform, exact sanitized command, expected result, actual result, and
the smallest synthetic reproduction possible.

Never publish credentials, private keys, customer data, private repository
content, signed URLs, or unredacted generated reports.

## Security reports

Follow [SECURITY.md](SECURITY.md) and use GitHub private vulnerability reporting.
Do not disclose a suspected vulnerability or reproduction payload in a public
issue.

## Operational boundary

Community support cannot act as an emergency production-response service.
Retain independent authorization, deployment, backup, rollback, and incident
controls when evaluating OpsCustodian.
